# Short regression benchmark

Run `SPINEL=/path/to/spinel bench/regression.sh` with `wrk`, `k6`, `oha`, and the platform profiler installed. The runner builds one Spinel server and exercises text, JSON, streamed text, gzip text, and gzip streams in inline, lanes, and base server modes with all three clients. It checks status and body markers with `wrk` and `k6`; both require the gzip response header for compressed routes. `oha` checks that all responses are HTTP 200 and waits for in-flight requests to finish before reporting. Every measured round has a concurrent system stack sample: macOS saves `sample` text at 1 ms intervals, and Linux saves `perf record -g` data at 999 Hz. The server is compiled with Spinel `--profile` for symbolized stacks. Warm-ups are not sampled.

Defaults are 25 connections, a one second warm-up, three ten second samples, and one application worker. Sampling is enabled by default; the measured rates then come from the `--profile` binary and should be compared with other profile runs. `MODES`, `FEATURES`, and `CLIENTS` can select a subset for a focused run. GC stats are enabled in every run and summarized in `gc.tsv`, including collection deltas, GC time as a share of the measurement window, and the latest live object/string heap sizes. The GC time share is approximate because Spinel reports GC time rounded to 0.01 seconds. `gc_snapshot_updated=0` means there was no new GC report in that measurement window, so live heap sizes are from the last collection. The runner also records process CPU seconds and CPU microseconds per completed request in `summary.tsv`; oha request counts are estimated from its measured duration and rate. Set `MEMORY=1` to additionally enable `SPINEL_ALLOC_REPORT` and `SPINEL_ALLOC_SITES=1`; the runner snapshots cumulative counters around each measured request window and writes per-site count/byte deltas and total allocated bytes per request to `allocations.tsv`. It also records process RSS before and after each window in `resident.tsv`. Allocation-site tracking has substantial overhead, so those throughput numbers are diagnostic and should not be compared with runs where `MEMORY=0`. Set `SAMPLE=0` for ordinary optimized throughput runs without stack sampling. Set `SAMPLE_INTERVAL` on macOS or `SAMPLE_FREQUENCY` on Linux to adjust the sample rate. Other controls are `CONNECTIONS`, `DURATION`, `WARMUP`, `ROUNDS`, `KILN_WORKERS`, `PORT`, and `RESULTS_DIR`. Repeat the run with each desired `KILN_WORKERS` value; increasing workers selects the Base shard count and the number of independent event loops. Raw client output, profiler samples, GC snapshots, server logs, and run metadata are saved under `/tmp/kiln-regression/` by default; `summary.tsv` contains each sample and `median.tsv` is the compact comparison table.

The default matrix has 45 warm-up runs and 135 measured runs, with one profiler sample per measured run. Compare medians from the same client on the same machine with the same tool versions and settings; clients produce different absolute rates.
